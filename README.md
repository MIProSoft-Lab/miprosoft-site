# miprosoft-site

A multilingual research group website for GitHub Pages that keeps itself up to
date from [ORCID](https://orcid.org), styled after the UIB's visual identity:
a home page with latest news, the team and latest publications; a team page
with members and collaborators; a page per member; a research section with the
research lines, the group's publications and supervised theses; multilingual
news and blog posts; and the courses the group teaches.

Every Monday (and on every push) a GitHub Action:

1. Downloads the public ORCID record of every member into `data/orcid/<orcid>.json`
2. Enriches each unique article **once**, however many members list it, and
   stores the result in `data/works.json`: authors, venues and abstracts come
   from Crossref, SISTEDES and Semantic Scholar, and citations and open access
   from OpenAlex
3. Commits the data if anything changed
4. Builds the site in every configured language
5. Deploys to GitHub Pages

## Layout

| Path | What |
| --- | --- |
| `site.config.yaml` | Group name, description and institution, **members** (`id` + ORCID iD), languages, profile sections, features |
| `data/people/<id>.yaml` | Per-member content ORCID lacks: name variants, title, teaching, talks…, plus per-member overrides (selected works, hidden items) |
| `data/overrides.yaml` | Corrections to works (by DOI) applied for every member |
| `content/news/<slug>/index.yaml` | News and blog posts, every language in one file, with their images beside it (*CMS*) |
| `content/courses/<slug>.yaml` | Courses the group currently teaches (*CMS*) |
| `content/transfer/<slug>.yaml` | Knowledge transfer tools (*CMS*) |
| `content/research-lines/<slug>.yaml` | Research lines (*CMS*) |
| `content/theses/<slug>.yaml` | PhD, master's and bachelor's theses supervised by members (*CMS*) |
| `content/collaborators/<slug>.yaml` | Collaborators shown on the team page (*CMS*) |
| `content/translations/<lang>.yaml` | Interface texts: menus, labels, buttons (*CMS*) |
| `data/jcr.yaml` | Journal Impact Factors entered by hand |
| `data/orcid/<orcid>.json` | *Fetched.* One ORCID record per member, with references to their works |
| `data/works.json` | *Fetched.* One entry per article (by DOI, or handle for SISTEDES), shared by all members |

Pages:

- `/<lang>/`: home page: latest news, the team and latest publications
- `/<lang>/team/`: members (principal investigators first) and collaborators
- `/<lang>/team/<id>/`: a member's profile
- Research (a menu in the navigation; `/<lang>/research/` goes to the first page):
  - `/<lang>/research/lines/`: research lines
  - `/<lang>/research/publications/`: the group's publications, each paper once
  - `/<lang>/research/theses/`: supervised theses, by type (also listed on each
    supervisor's profile, under "Supervised theses")
- `/<lang>/news/` and `/<lang>/news/<slug>/`: news and blog posts
- Teaching & Transfer (a menu in the navigation; each page is hidden when it has no content):
  - `/<lang>/teaching/courses/`: courses the group currently teaches
  - `/<lang>/teaching/transfer/`: knowledge transfer: tools the group has developed
    for companies and society

Members' names in author lists link to their profiles.

## Editing content

News, research lines, theses, courses, knowledge transfer tools, collaborators and the interface texts can be edited without touching code, in
the content editor ([Sveltia CMS](https://sveltiacms.app)) at **`/admin/`** of
the site, e.g. `https://<site>/admin/`. It shows every language side by side
and commits each change to the repository, which rebuilds and publishes the
site (a couple of minutes).

Signing in:

- **On the published site**: "Sign In Using Access Token" with a GitHub
  [personal access token](https://github.com/settings/personal-access-tokens)
  that can read and write the repository's *Contents* (the sign-in dialog
  links to a pre-filled token page). Editors need write access to the repository.
- **"Sign In with GitHub"** (friendlier for non-technical editors) needs an OAuth
  client such as [Sveltia CMS Authenticator](https://github.com/sveltia/sveltia-cms-auth),
  a free Cloudflare Worker. Deploy it, then set `cms.authUrl` in
  `site.config.yaml`.
- **Locally**: run `npm run dev`, open `http://localhost:4321/admin/`
  in Chrome or Edge, click "Work with Local Repository" and pick this folder.
  Changes are written to the files; commit them with Git.

The editor has the site's look: UIB blue, the light blue tint, UIB sans and the
group's logo (`public/admin/logo.png`). The colours and fonts are CSS variables
in `public/admin/index.html`, and entry previews use `public/admin/preview.css`,
which follows the site's post pages.

The editor's configuration, `public/admin/config.yml`, is generated by
`scripts/cms-config.mjs` before every `npm run dev` and `npm run build`, from
`site.config.yaml` (languages, repository), the members (for authors and
instructors) and `content/translations/en.yaml` (one field per text). Run
`npm run cms:config` after changing any of them.

### Files

Every entry is one YAML file holding all the languages. The default language
(`en`) has all the fields; the others only the translated ones. A language that
is missing is shown in English, with a notice on news posts.

```yaml
# content/news/new-website/index.yaml
en:
  title: Our new website
  date: 2026-11-02
  kind: news                 # news | blog
  authors: [antonio-crespi]  # member ids: linked to their profiles
  guestAuthors: [Jane Doe]   # anyone else
  image: cover.jpg           # optional, in the same folder
  imageAlt: What the picture shows
  summary: One or two sentences for the cards (optional).
  body: |
    The text, in Markdown. ![A picture](photo.jpg)
ca:
  title: El nostre nou web
  body: |
    …
```

Courses (`content/courses/<slug>.yaml`) work the same way: `title`, `summary`,
`schedule` and `institution` are translated; `order`, `type` (`master`,
`postgraduate`, `short`, `workshop`, `online`), `instructors`,
`guestInstructors`, `start`/`end` (`2027` or `2027-02`), `format` (`in-person`,
`online`, `hybrid`), `languages`, `ects`/`hours` and `url` are shared. With no
courses, the Courses tab disappears.

Interface texts (`content/translations/<lang>.yaml`) keep `{n}`, `{total}`,
`{year}` and `{language}` as placeholders for values, and `one`/`other` for
texts that depend on a number. A text left empty in Catalan or Spanish is shown
in English.

The home page shows the three latest posts. The files under `content/` include a sample post, course, tool, collaborator,
research line and two theses with placeholder text: replace or delete them.

## Adding a member

1. Add `{ id: jane-doe, orcid: 0000-0000-0000-0000 }` under `members` in `site.config.yaml`
   (add `pi: true` to mark a principal investigator: they get an "IP" badge and
   are listed first)
2. Optionally create `data/people/jane-doe.yaml` (copy an existing one as a template)
3. Run `npm run fetch`: only the articles that are not already in `data/works.json` are fetched

When a member is removed, the next fetch deletes their ORCID record and any
articles no remaining member lists.

## Fetching

Article metadata that rarely changes (authors, venue, pages, abstracts) is kept
from earlier runs and refetched only after `fetch.refreshDays` (30 by default).
Citations and open-access status are refreshed on every run, in batches.

```sh
npm run fetch                 # ORCID records + new or stale articles + citations
npm run fetch -- --refresh    # refetch all article metadata now
npm run fetch -- --no-enrich  # ORCID records only
```

Optional API keys (as environment variables locally, or repository secrets in
CI): `OPENALEX_API_KEY` and `SEMANTIC_SCHOLAR_API_KEY`. Without a key, both
APIs have tight shared rate limits.

## Local development

Requires Node >= 22.23 (Astro 7).

```sh
npm install
npm run fetch
npm run dev
```

## Journal Impact Factors

Journal articles show the JIF (Clarivate JCR) of their publication year, or the
latest available year. Enter the values by hand in `data/jcr.yaml`.

To fetch them automatically from the Clarivate Journals API instead, add an API
key with JCR access as the `CLARIVATE_API_KEY` repository secret (or run
`CLARIVATE_API_KEY=… npm run fetch:jcr` locally). It writes `data/jcr.json` for
the journals of all members; values in `data/jcr.yaml` still take precedence.

## Style

Colours follow the UIB's visual identity: institutional blue (Pantone 300 C,
`#0065BD`), black, and the light blue tint `#E7EDF7`, with a dark theme that
follows the system (or the toggle in the top bar). Everything is in
`src/styles/site.css`, with the colours as variables at the top.

The site uses UIB sans, the University of the Balearic Islands' institutional
typeface, © 2014 Damià Rotger Miró ([ductilct.com](https://www.ductilct.com)).
